# Phase 3候補整理

作成日: 2026-05-10

## 方針

Phase 3は、Phase 2で作った運用基盤を大きく壊さず、現場運用で困りやすい部分から小さく改善します。
現時点ではCloud Functionsなしの構成を維持し、React、TypeScript、Firebase Authentication、Firestore、Hostingで対応できる内容を優先します。

## 優先候補

| 優先 | 候補 | 目的 | 主な作業 | 判断ポイント |
| --- | --- | --- | --- | --- |
| A | Phase 2本番運用手順書 | 管理者が迷わず日次運用できるようにする | ログイン、対象日選択、CSV取込、テンプレート作成、履歴確認、復旧手順を整理 | 実運用開始前に必要 |

## Phase 3に入れる前に決めること

- Phase 3の最優先は「運用手順」か「画面改善」か。
- CSV取込で既存データの上書きを許可するか。
- Excel出力はCSVのままで足りるか、`.xlsx`が必要か。
- 分析は日次確認で足りるか、週次・月次比較が必要か。
- GitHub Actionsで自動テストを回す運用にするか。
- Cloud Functionsなしを継続するか、将来の集計だけ別フェーズで検討するか。

## おすすめの着手順

1. Phase 2残り確認を完了する。
2. 実機スマホ確認で見つかったUI不便を小さく直す。
3. 管理者向けの本番運用手順書を作る。
4. CSV取込の実運用頻度を見て、上書きモードの要否を判断する。
5. 無料枠の残量が気になり始めたら、期間指定CSVの控え運用と物理削除手順を分けて決める。
6. 必要になったら、Excel出力、期間比較、CIテストへ進む。

## Phase 3ではまだ急がない候補

- 大規模データ向けの仮想スクロール
- Cloud Functionsによるサーバー側集計
- 複雑な承認ワークフロー
- 外部システム連携

これらは便利ですが、今のPhase 2確認が終わる前に入れると、確認範囲が広がりすぎます。
