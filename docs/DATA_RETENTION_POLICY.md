# データ保管・過去データ運用方針

作成日: 2026-05-10

## 現在の動き

YardManagerの便・タスク・便紐付け・操作履歴は、`siteId`と`businessDate`を持っています。
各画面は、ログインユーザーの`siteId`と画面右上の対象日`businessDate`で絞り込んで表示します。

つまり、過去日の便データは自動では消えません。
対象日を過去日に切り替えると、その日の便・タスク・操作履歴を確認できます。
管理画面の`過去データ`では、期間を指定して保管量の目安を確認できます。

## 無料枠を優先する方針

過去データは、詳細に参照し続けるよりも、Firebaseの無料枠で運用できる範囲まで残す方針にします。
そのため、長期保存が必要な場合はCSV出力で控えを取り、アプリ内のFirestoreデータは必要以上に増やし続けない運用を基本にします。

Cloud Firestoreの無料枠は、保存容量、読み取り、書き込み、削除、転送量で決まります。
2026-05-10時点のFirebase公式ドキュメントでは、Firestoreの無料枠は保存データ1GiB、読み取り50,000回/日、書き込み20,000回/日、削除20,000回/日、転送10GiB/月です。
最新値はFirebase公式ドキュメント（https://firebase.google.com/docs/firestore/pricing）で確認してください。

## 削除の扱い

アプリ上の削除は、物理削除ではなく`deleted: true`による論理削除です。
Firestore Security Rulesでは物理削除を禁止しています。

この設計にしている理由は次の通りです。

- 誤削除したときに履歴を追いやすい
- 実績時刻や操作履歴との整合性を壊しにくい
- 作業記録をあとから確認しやすい

ただし、通常画面では`deleted: true`のデータは表示対象から外れます。

## 操作履歴の扱い

`operationLogs`は更新・削除できない前提です。
誰が、いつ、何を作成・更新・論理削除・ステータス変更したかを残す監査ログとして扱います。

操作履歴も`businessDate`を持っているため、対象日を切り替えて日別に確認します。

## データ量が増えたときの影響

現状の画面は、基本的に対象日単位で読み込みます。
そのため、過去データが増えても、日々の画面表示がすぐ重くなる設計ではありません。

ただし、次のような運用になった場合は追加対策を検討します。

- 1日あたりの便・タスクが数百件以上になる
- 過去数か月分を横断して分析したい
- 操作履歴が非常に多くなる
- 削除済みデータも含めた監査画面が必要になる

## 推奨運用

当面は、無料枠に十分収まる範囲では過去データを残す運用を推奨します。

理由は、Phase 2時点では日別表示が中心で、実績確認・履歴確認の価値が高いためです。
削除やアーカイブを急ぐより、まずは実運用でどの程度データが増えるかを見るほうが安全です。

おすすめの運用は次の通りです。

1. 直近の便・タスク・操作履歴はそのまま残す。
2. 月末または週末に`CSV出力`の期間指定CSVで控えを取る。
3. 詳細参照が不要になった古い日付は、削除・アーカイブ対象として扱う。
4. 明らかなテストデータは、画面上の削除操作で論理削除する。
5. 論理削除済みデータもFirestore上には残るため、無料枠が近づいたら物理削除手順を別途決める。

## 将来の追加候補

Phase 3以降で検討できる改善は次の通りです。

| 候補 | 内容 | 注意点 |
| --- | --- | --- |
| 保管量目安画面 | 期間内の主要ドキュメント数、削除済み件数を確認する | 実装済み |
| 期間指定CSV出力 | 指定期間の便・タスク・便紐付け・履歴を控えとして出力する | 実装済み。必要な期間だけ手動読込 |
| アーカイブ済みフラグ | 古いデータに`archived: true`を付ける | 通常画面と監査画面の表示条件を分ける |
| 物理削除手順 | 法的・運用上不要になった古いデータを削除する | 操作履歴や実績との整合性確認が必要 |
| Cloud Functionsでの定期処理 | 自動アーカイブや月次集計を行う | 現在のCloud Functionsなし方針とは別フェーズ |

## 現時点の結論

今は、無料枠に収まる範囲で過去の便・タスク・操作履歴を残す形で運用します。
画面は対象日で絞り込まれるため、日々の操作では対象日のデータだけを扱います。

本格的なアーカイブや削除ルールは、実運用でデータ量と無料枠への影響が見えてから決めるのが安全です。
