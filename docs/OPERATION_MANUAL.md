# YardManager本番運用手順書

作成日: 2026-05-10

## 目的

この手順書は、管理者がYardManagerを日々の運用で使うための基本手順をまとめたものです。
本番データを増やす操作は、対象日とプレビュー結果を確認してから実行します。

## 1. ログインと対象日確認

1. 公開URLを開きます。

```text
https://new-yard-kanri.web.app/
```

2. 管理者アカウントでログインします。
3. 画面右上の対象日を確認します。
4. 別の日付を確認する場合は、対象日を変更します。

対象日を間違えると、別日の便・タスクを作成する可能性があります。
CSV取込やテンプレート作成の前には必ず対象日を確認してください。

## 2. 日次状況確認

1. `ダッシュボード`を開きます。
2. 便数、タスク数、前工程待ち、実績開始件数を確認します。
3. 作業員別タスク進捗を確認します。
4. ステーション別便進捗を確認します。
5. 作業中タスクと次の未完了タスクを確認します。

## 3. 手入力で便・タスクを作成する

### 便を作成する

1. `便管理`を開きます。
2. 便名、便番号、種別、ステーション、予定時刻を入力します。
3. 保存前チェックを確認します。
4. 致命的なエラーがなければ保存します。

同じ便番号や時間かぶりがある場合は警告が表示されます。
警告だけの場合は保存できますが、内容を確認してから実行してください。

### タスクを作成する

1. `タスク管理`を開きます。
2. タスク名、作業員、レーン、対象便、予定時刻を入力します。
3. 保存前チェックを確認します。
4. 致命的なエラーがなければ保存します。

## 4. CSV取込で作成する

CSV取込は新規登録のみです。既存の便・タスクは上書きしません。

1. `CSV取込`を開きます。
2. 取込対象を`便`または`タスク`にします。
3. 必要に応じて`テンプレート出力`からCSVテンプレートを出力します。
4. CSVを選択します。少量確認の場合は、`CSV本文を貼り付け`にCSV本文を貼り付けて読み込むこともできます。
5. プレビューの判定を確認します。CSVに`対象日`列がある場合は、画面右上の対象日と一致していることも確認されます。
6. `登録予定`、`スキップ`、`要修正`、`登録後目安`の件数を確認します。
7. 要修正がある場合は、エラー行CSVまたは判定CSVを出力して直します。
8. `対象日・登録件数・スキップ内容を確認しました`にチェックします。
9. 問題がなければ新規登録を押し、最終確認画面で対象日・件数・登録後目安・上書きしないことを確認して登録します。
10. 登録後、便管理またはタスク管理で反映を確認します。
11. 操作履歴にCSV取込の記録が残っていることを確認します。

最初の本番確認では、テスト用の日付で1件だけ登録してください。
大量登録の場合は、登録前に`判定CSV出力`で控えを残してください。

## 5. ダイヤテンプレートで作成する

1. `テンプレート`を開きます。
2. `計画作成`で作成したいテンプレートを選びます。
3. 開始日と終了日を指定します。一括操作は最大31日分です。
4. 実行モードを選びます。
   - `新規作成`: 既存計画を残したまま新規作成します。
   - `再作成/上書き（実績なしのみ）`: 実績なしの既存計画を論理削除してから作り直します。
   - `一括削除（実績なしのみ）`: テンプレート由来の実績なし計画だけを論理削除します。
5. 画面の作成予定件数と注意表示を確認します。
6. `実行前チェック`を押し、既存対象・作成予定・削除予定・実績あり件数を確認します。
7. `対象期間・件数・実績なし条件を確認しました`にチェックします。
8. 問題がなければテンプレート作成を実行します。
9. 作成結果に便・タスクの詳細が表示されることを確認します。
10. 操作履歴に作成記録が残っていることを確認します。

既存データは上書きされません。
再作成/上書きは、物理削除ではなく論理削除と再作成として記録されます。
作業開始済み・完了済み・実績時刻ありのデータが含まれる場合は、再作成/一括削除できません。

### テンプレートそのものをCSVで登録する

1. `テンプレート`を開きます。
2. `テンプレート管理`を開きます。
3. `テンプレートCSV取込`でCSVテンプレートを出力します。
4. テンプレート名、便行、タスク行をCSVに入力します。
5. CSVを読み込み、テンプレート単位の`登録予定`、`既存スキップ`、`要修正`を確認します。
6. 問題がなければ登録前確認を押し、最終確認後に登録します。

同名テンプレートは上書きされず、スキップされます。

## 6. 作業員画面の確認

1. 管理者で`作業カード`を開き、確認する作業員を選択します。
2. 実際の一般ユーザー画面と同じ作業カードが表示されることを確認します。
3. スマホ実機で、カードが横スクロール前提になっていないことを確認します。
4. `作業開始`、`作業完了`、`未完了に戻す`のボタンが押しやすいことを確認します。
5. 一般ユーザーでログインできる場合は、自分に割り当てられたタスクだけが表示されることを確認します。
6. 操作後に実績時刻と操作履歴が記録されることを確認します。

作業員の`users/{uid}.workerId`には、作業員名ではなく`workers`コレクションのドキュメントIDを設定します。

## 7. CSV出力

1. `CSV出力`を開きます。
2. 便一覧CSV、タスク一覧CSV、操作履歴CSVを出力します。
3. Excelで開き、日本語が文字化けしないことを確認します。
4. 月末や週末の控えを取る場合は、`期間指定の控えCSV`で開始日・終了日を選びます。
5. `期間データを読み込む`を押し、件数を確認してから、便・タスク・便紐付け・履歴のCSVを出力します。

期間指定CSVは、画面を開いただけでは広い期間を読み込みません。
必要な期間だけ手動で読み込むことで、Firestoreの読み取り回数を増やしすぎない運用にします。

## 8. 実績確認

1. `実績分析`を開きます。
2. 完了率、平均時間、開始遅れ件数を確認します。
3. 作業員別実績とステーション別実績を確認します。
4. 実績時刻がないデータがあっても画面が壊れないことを確認します。

## 9. 過去データ確認

1. 画面右上の対象日を過去日に変更します。
2. ダッシュボード、便管理、タスク管理、操作履歴を確認します。
3. 必要に応じて`CSV出力`からその日の控え、または期間指定の控えCSVを出力します。
4. `過去データ`を開くと、期間内の保管量の目安をまとめて確認できます。

過去データは自動では消えません。
ただし、詳細参照を長く続ける目的ではなく、Firebaseの無料枠で運用できる範囲まで残す方針です。
詳しい方針は、`docs/DATA_RETENTION_POLICY.md`を確認してください。

## 10. トラブル時の確認

| 症状 | 確認すること |
| --- | --- |
| ログイン後に使えない | `users/{uid}`が存在するか、`active`が`true`か確認する |
| 一般ユーザーに作業が出ない | `users/{uid}.workerId`とタスクの`workerId`が一致しているか確認する |
| CSV取込できない | プレビューの要修正理由、必須列、時刻形式、マスタ名を確認する |
| テンプレート作成できない | 有効なステーション、レーン、作業員が足りているか確認する |
| RulesテストがJavaで止まる | Microsoft OpenJDK 21のbinがPATHに入っているか確認する |

## 11. 開発・確認コマンド

```powershell
npm.cmd run lint
npm.cmd run build
npm.cmd run test:rules
```

RulesテストでJavaが見つからない場合:

```powershell
$env:Path = "C:\Program Files\Microsoft\jdk-21.0.11.10-hotspot\bin;$env:Path"
npm.cmd run test:rules
```

`PERMISSION_DENIED`ログが出ても、拒否されるべき操作の確認であれば正常です。
