# Phase 2開発計画

Phase 2では、Phase 1で作った日次運用の土台に対して、見える化、入出力、分析を段階的に追加します。

## 優先順位

| 優先 | 機能 | 目的 | 状態 |
| --- | --- | --- | --- |
| 1 | ダッシュボード | 当日の便・タスク進捗をすぐ把握する | 実装済み |
| 2 | Excel/CSV出力 | 当日計画・実績を外部共有しやすくする | 実装済み |
| 3 | Excel/CSV取込 | 便・タスク計画をまとめて登録する | 新規登録・判定改善まで実装済み |
| 4 | 実績分析 | 作業時間、完了率、遅れを振り返る | 実装済み |
| 5 | ダイヤテンプレート | 定型便・定型タスクを再利用する | 実装済み |
| 6 | 入力改善 | フォーム操作、入力チェック、エラー表示を改善する | 主要フォーム実装済み |
| 7 | Rules自動テスト | 権限事故を自動検知する | 代表シナリオ実装済み |

## Phase 2-1 ダッシュボード

管理者向けに、対象日の状況を集計する画面を追加しました。

- 便数、タスク数、前工程待ち、実績開始件数
- 作業員別タスク進捗
- ステーション別便進捗
- 作業中タスク
- 次の未完了タスク

Firestoreの既存データを購読して集計するだけなので、Cloud Functionsは使いません。

## Phase 2-2 CSV出力

管理者向けに、対象日のデータをCSVで保存する画面を追加しました。

- 当日の便一覧
- 当日のタスク一覧
- 実績時刻
- 操作履歴

CSVはExcelで開きやすいようにBOM付きUTF-8で出力します。Cloud Functionsは使わず、ブラウザ内で生成します。

## Phase 2-3 CSV取込

管理者向けに、CSVを登録前に確認し、問題がなければ新規登録できる画面を追加しました。

- 便取込テンプレートの出力
- タスク取込テンプレートの出力
- CSVファイルの読み込み
- 必須列チェック
- ステーション、作業員、レーンのマスタ照合
- 対象便番号によるメイン便照合
- 既存データとの重複チェック
- CSV内のステーション、作業員、レーン時間かぶりチェック
- エラー行だけのCSV再出力
- HH:mm形式の時刻チェック
- 状態値のチェック
- 先頭20件のプレビュー
- 便・タスクの新規登録
- 登録時のoperationLogs記録
- 取込結果の詳細表示
- 既存データのスキップモード
- スキップ行CSV出力
- 判定CSV出力
- プレビューの判定別絞り込み
- 登録できない理由の表示

データ破壊リスクを避けるため、取込は新規追加のみです。既存の便・タスクは上書きしません。

## Phase 2-4 実績分析

管理者向けに、対象日の作業実績を集計する画面を追加しました。

- タスク完了率
- 便完了率
- 平均タスク時間
- 開始遅れ件数
- 作業員別タスク実績
- ステーション別便実績
- 実績記録済み件数

平均時間は開始・完了の両方が記録されたデータだけで計算します。開始遅れは予定開始から5分超で判定します。

## Phase 2-5 ダイヤテンプレート

管理者向けに、定型の便・タスクを対象日にまとめて作成する画面を追加しました。

- 午前基本ダイヤ
- 日中標準ダイヤ
- 作成予定の便・タスクのプレビュー
- 有効なステーション、レーン、作業員を利用した自動割当
- 既存便番号の重複チェック
- 既存便・既存タスクとの時間かぶりチェック
- 新規作成のみで、既存データは上書きしない
- 作成時のoperationLogs記録
- 作成結果の詳細表示

テンプレートはブラウザ側で生成し、Cloud Functionsは使いません。

## Phase 2-6 入力改善

管理者向けの手入力フォームに、保存前チェックを追加しました。

- 便フォームの必須入力チェック
- 便フォームの時刻前後チェック
- 便番号重複、ステーション時間かぶりの警告表示
- タスクフォームの必須入力チェック
- タスクフォームの時刻前後チェック
- 作業員、レーン、対象便の重複・時間かぶり警告表示
- ステーション、レーン、作業員マスタの必須入力チェック
- マスタ名称重複の警告表示
- ユーザー設定のUID、メール、権限、作業員紐付けチェック
- ログイン中管理者の無効化・一般ユーザー化防止
- サブ便/メイン便紐付けの選択漏れ・重複チェック
- 保存前チェック結果をフォーム内に表示
- 致命的な入力不足がある場合は保存ボタンを無効化

## Phase 2-7 Rules自動テスト

Firestore Emulatorを使ったSecurity Rules自動テストを追加しました。

- 未ログインユーザーが計画データを読めないこと
- 管理者が同一siteIdの計画データを作成できること
- 管理者でも別siteIdの計画データを作成できないこと
- 一般ユーザーが自分のタスクだけ読めること
- 一般ユーザーが計画内容を書き換えられないこと
- 一般ユーザーが自分のタスクの状態と実績時刻だけ更新できること
- 一般ユーザーが自分のタスク状態変更ログだけ作成できること

実行コマンド:

```powershell
npm.cmd run test:rules
```

Firestore Emulatorの起動にはJavaが必要です。Javaがない環境では、`Could not spawn java -version` で停止します。

## 次に着手する候補

- 将来的な上書き取込モードの要否
- ダイヤテンプレート画面の細かな入力補助
- Java導入後のRules自動テスト実行確認
- CI環境でのRules自動テスト実行
