# Phase 3 ダイヤテンプレート管理 実装計画

作成日: 2026-05-10

## 現状

現在の`ダイヤテンプレート`画面には、テンプレートから対象日の便・タスクを新規作成する機能があります。
ただし、テンプレート定義そのものは`src/features/TemplateGenerationView.tsx`内に固定で書かれています。

そのため、管理者が画面から次の操作を行う機能は未実装です。

- テンプレートを新規作成する
- 既存テンプレートを編集する
- 既存テンプレートを複製する
- 使わなくなったテンプレートを無効化する
- テンプレート内の便・タスク行を増減する

## 結論

ダイヤテンプレート管理はPhase 3の必須候補として実装します。
実運用では、曜日別、時間帯別、繁忙日用などの定型パターンが増えるため、コード変更なしで管理者がテンプレートを調整できる必要があります。

## 実装方針

Cloud Functionsなしの方針を維持し、React + TypeScript + Firestore + Hostingだけで実装します。

Firestoreには次のようなコレクションを追加する想定です。

```text
dialTemplates
```

主なフィールド案:

| フィールド | 内容 |
| --- | --- |
| `siteId` | 拠点ID |
| `businessDate` | マスタ扱いの日付。既存マスタと同じく固定値を使う想定 |
| `name` | テンプレート名 |
| `description` | 説明 |
| `active` | 使用可否 |
| `routes` | 作成予定の便行配列 |
| `tasks` | 作成予定のタスク行配列 |
| `createdAt` / `createdBy` | 作成監査 |
| `updatedAt` / `updatedBy` | 更新監査 |
| `deleted` | 論理削除 |

`routes`と`tasks`は、まずはテンプレート1件の中に配列として持たせます。
テンプレート件数・行数が大きくなった場合だけ、サブコレクション化を検討します。

テンプレートから作成した便・タスクには、後から一括確認や再作成ができるように次のメタ情報を持たせます。

| フィールド | 内容 |
| --- | --- |
| `templateId` | 元テンプレートID |
| `templateName` | 作成時点のテンプレート名 |
| `templateRunId` | 一括作成単位のID |
| `templateRunLabel` | 画面表示用の一括作成名 |

また、一括作成の履歴として次のコレクションを追加する想定です。

```text
templateRuns
```

主なフィールド案:

| フィールド | 内容 |
| --- | --- |
| `siteId` | 拠点ID |
| `templateId` | 使用したテンプレートID |
| `templateName` | 作成時点のテンプレート名 |
| `startDate` / `endDate` | 一括作成した対象期間 |
| `days` | 作成日数 |
| `routeCount` / `taskCount` | 作成件数 |
| `mode` | `create` / `recreate` / `overwrite` |
| `status` | `completed` / `partially_failed` |
| `createdAt` / `createdBy` | 実行監査 |

## 画面案

既存の`テンプレート`画面を次の2つの役割に分けます。

| 画面 | 目的 |
| --- | --- |
| テンプレート作成 | 選択したテンプレートから対象日の便・タスクを作成する |
| テンプレート管理 | テンプレートそのものを作成・編集・複製・無効化する |

テンプレート管理で必要な操作:

1. テンプレート一覧を表示する。
2. 新規テンプレートを作成する。
3. テンプレート名・説明を編集する。
4. 便行を追加・編集・削除する。
5. タスク行を追加・編集・削除する。
6. 既存テンプレートを複製して別パターンを作る。
7. 使わないテンプレートを無効化する。
8. 保存前チェックで、時刻形式、対象便、作業員、レーン、重複を確認する。

## 期間指定の一括作成

毎日テンプレート作成を実行する負担を減らすため、テンプレートから複数日分の便・タスクをまとめて作成できるようにします。

ただし、Firestoreの無料枠と誤登録リスクを考慮して、まとめて作成できる期間は最大1か月分に制限します。
実装上は、開始日から終了日までを最大31日までにします。

一括作成のルール:

- 開始日と終了日を指定する。
- 作成可能な最大日数は31日。
- 32日以上は保存前チェックでブロックする。
- 対象期間内の各`businessDate`に対して、同じテンプレート内容で便・タスクを作成する。
- 既存データは通常モードでは上書きしない。
- 作成前に、日数、便件数、タスク件数、合計書き込み目安を表示する。
- 実行前に「対象期間・件数・上書きしないこと」を確認するチェックを必須にする。

件数表示例:

```text
対象期間: 2026-06-01 - 2026-06-30
対象日数: 30日
作成予定: 便 90件 / タスク 90件
上書き: しない
```

## 再作成・一括削除・上書き

登録後に計画変更があり、テンプレートから作り直したいケースに対応します。

ただし、実績が入ったデータを消したり上書きしたりすると、現場の作業記録が壊れます。
そのため、一括削除・再作成・上書きは、実績がない計画データだけを対象にします。

### 一括削除

一括削除は、テンプレート作成で作られた対象期間の便・タスク・便紐付けを論理削除します。

削除できる条件:

- 対象データに`actualStartAt`がない
- 対象データに`actualEndAt`がない
- 対象データが作業中または完了ではない
- 対象期間が最大31日以内
- 実行前に対象日数・削除件数・実績なしを確認する

削除できない条件:

- 便またはタスクに開始実績がある
- 便またはタスクに完了実績がある
- 作業中または完了ステータスがある
- 対象期間が31日を超える

### 再作成

再作成は、次の順番で実行します。

1. 対象期間の既存テンプレート作成データを確認する。
2. 実績があるデータがあれば処理を止める。
3. 実績がないデータだけを論理削除する。
4. 同じ対象期間にテンプレートから新しく便・タスクを作成する。
5. 操作履歴に削除と作成の両方を残す。

### 上書き

上書きは、既存ドキュメントを直接書き換えるのではなく、実績なしデータの論理削除と再作成として扱います。
これにより、操作履歴と作成時点のテンプレート内容を追いやすくします。

画面上の表現は`上書き`でも、内部処理は次の形にします。

```text
実績なし確認 → 既存計画を論理削除 → 新しい計画を作成
```

## 実行確認

一括作成・一括削除・再作成・上書きは、すべて画面内の最終確認を必須にします。

確認画面に表示する内容:

- 対象テンプレート
- 対象期間
- 対象日数
- 作成予定件数または削除予定件数
- 実績ありデータの有無
- 上書きするか、上書きしないか
- 実行後に戻せない範囲

実行ボタンは、確認チェックを入れるまで押せないようにします。

## 無料枠への配慮

一括作成は便利ですが、データを一気に増やします。
そのため、次の制限を入れます。

- 一括作成は最大31日分まで。
- 一括削除・再作成・上書きも最大31日分まで。
- 実行前に書き込み件数の目安を表示する。
- 大量作成後は`過去データ`と`期間指定CSV`で保管量を確認する。
- Cloud Functionsは使わず、管理者画面から手動実行する。

## 保存前チェック

テンプレート保存時に、次を確認します。

- テンプレート名が空でない
- 便番号がテンプレート内で重複していない
- タスクの対象便がテンプレート内に存在する
- 予定終了が予定開始より後
- 作業員・レーン・ステーション参照が有効
- 同じ作業員やレーンの時間かぶりがない
- 無効なマスタを新規テンプレートに使わない
- 一括作成期間が31日以内
- 再作成・上書き対象に実績ありデータが含まれていない

## セキュリティ方針

テンプレート管理は管理者のみ作成・更新・論理削除できます。
一般ユーザーはテンプレートを読む必要がないため、読み取りも管理者に限定する想定です。

Firestore Security Rulesに`dialTemplates`を追加し、次の方針にします。

- 管理者: 同一`siteId`のテンプレートを読み書き可能
- 一般ユーザー: 読み書き不可
- 物理削除: 禁止

`templateRuns`も管理者のみ読み書き可能にします。
一括削除・再作成・上書きでも、便・タスク・便紐付けは物理削除せず、既存方針どおり論理削除にします。

## 移行方針

初回実装時は、現在コード内にある固定テンプレートを初期データとして画面から登録できる形にします。
いきなり既存固定テンプレートを削除せず、次の順で移行します。

1. `dialTemplates`の型・Rules・画面を追加する。
2. テンプレート管理画面から同等テンプレートを登録する。
3. テンプレート作成画面をFirestore読込に切り替える。
4. 公開URLで既存テンプレートと同じ計画が作れることを確認する。
5. 固定テンプレート定義をフォールバックまたは削除対象にする。

## 優先度

優先度はAです。

理由:

- 実運用では定型ダイヤが現場ごとに変わる
- コード変更なしでテンプレートを増やせないと運用者が困る
- CSV取込よりも、定型パターン作成のほうが日次運用で使いやすい場面が多い
- ただし既存データを壊す機能ではないため、上書きCSVより先に実装しやすい

## 受入確認

実装後は次を確認します。

1. 管理者だけがテンプレート管理を開ける。
2. テンプレートを新規作成できる。
3. 便行・タスク行を追加できる。
4. 入力不備があると保存できない。
5. 既存テンプレートを複製できる。
6. 無効化したテンプレートは作成候補に出ない。
7. テンプレートから対象日に便・タスクを作成できる。
8. テンプレートから最大31日分まで一括作成できる。
9. 32日以上の一括作成は保存前チェックで止まる。
10. 実績がない一括作成データは、一括削除できる。
11. 実績がある便・タスクが含まれる場合、一括削除・再作成・上書きはできない。
12. 上書きは、実績なしデータの論理削除と再作成として操作履歴に残る。
13. 作成された便・タスクが便管理・タスク管理・操作履歴に出る。
14. `npm.cmd run lint`、`npm.cmd run build`、必要に応じて`npm.cmd run test:rules`が成功する。
